# Architecture

Reference for how this repo is organized, which dependencies are used and why, and the
rules a new domain must follow. Written so an AI agent can reproduce the same layout as a
starter template without reading every file.

**Project**: `taskboard-go-api` — a REST API built with the Go standard library plus small,
single-purpose libraries. No web framework (no Gin/Echo/Fiber), no ORM.

Go module path: `github.com/justKody/taskboard-go-api` (module lives in `server/`, not repo root).

---

## 1. Stack at a glance

| Concern | Choice | Notes |
| --- | --- | --- |
| HTTP server | `net/http` | `http.ListenAndServe`, plain `http.Handler` |
| Routing | `gorilla/mux` | subrouters, path vars, `.Use()` middleware |
| Database | PostgreSQL via `jackc/pgx/v5` | native pgx driver, **not** `database/sql` at runtime |
| Query layer | `sqlc` (codegen) | SQL is hand-written; Go is generated |
| Migrations | `golang-migrate/v4` | driven by a tiny in-repo CLI + Makefile |
| Validation | `go-playground/validator/v10` | struct tags on DTOs |
| Auth | `golang-jwt/jwt/v5` + `golang.org/x/crypto/bcrypt` | HS256, cookie **or** bearer header |
| Config | `joho/godotenv` + `os.LookupEnv` | eager global, loaded at package init |
| Build/tooling | `Makefile`, multi-stage `Dockerfile` | Alpine runtime, non-root user |
| Tests | none present | no `_test.go` files in the repo today |

### Dependency roles (from `server/go.mod`, Go 1.25.0)

Direct:

```
github.com/gorilla/mux                v1.8.1    router + path vars + middleware chain
github.com/jackc/pgx/v5               v5.10.0   Postgres driver; also the sqlc runtime target
github.com/golang-migrate/migrate/v4  v4.19.1   schema versioning (pgx/v5 + source/file drivers)
github.com/go-playground/validator/v10 v10.30.3 DTO validation via `validate:"..."` tags
github.com/golang-jwt/jwt/v5          v5.3.1    JWT create/parse with custom Claims
github.com/joho/godotenv              v1.5.1    .env loading (optional at runtime)
golang.org/x/crypto                   v0.54.0   bcrypt password hashing
```

Everything else in `go.mod` is indirect. `sqlc` itself is **not** a Go dependency — it is an
external binary run via `make sqlc`.

## 3. Layering & data flow

```text
HTTP request
   │
   ▼
mux Router  ──►  middleware.Logger  ──►  /api/v1 subrouter
                                              │
                              ┌───────────────┴────────────────┐
                              ▼                                ▼
                       public routes                   domain subrouter
                     (/login /signup /logout)          + middleware.Auth
                              │                                │
                              └────────────┬───────────────────┘
                                           ▼
                            service/<domain>/controllers.go   ← HTTP layer
                              utils.ParseJSON → DTO
                              utils.Validate.Struct
                              middleware.GetUserID(ctx)
                              authorization checks
                                           │
                                           ▼
                            service/<domain>/store.go          ← data layer
                              implements <Domain>Store iface
                              calls sqlc.Queries
                              maps sqlc row → types.X
                                           │
                                           ▼
                                  db/sqlc (generated)
                                           │
                                           ▼
                                   pgx → PostgreSQL
```

**Strict rules that hold everywhere in the codebase:**

1. `cmd/` never contains business logic — only wiring.
2. Controllers never touch `sqlc.Queries` directly; they go through a `Store` interface.
3. Stores never touch `http.ResponseWriter` — they return `(*types.X, error)`.
4. Only stores convert `sqlc.*` rows into `types.*` models.
5. All JSON writing goes through `utils.WriteJSON` / `utils.WriteError` — never `json.NewEncoder(w)` in a controller.
6. Handlers are always methods on `*Handler` and named `Handle<Verb><Noun>`.
7. `ctx` is always `r.Context()`, passed down as the first argument.

## 4. Per-domain file contract

Every routed domain package (`service/<domain>/`) has exactly four files:

### `dto.go` — request/response shapes, validation lives here

```go
package organization

type CreateOrganizationRequestDTO struct {
	Name string `json:"name" validate:"required"`
}

type OrganizationDetailsResponseDTO struct {
	Organization *types.Organization `json:"organization"`
	Members      []types.Membership  `json:"members"`
}
```

Naming: `<Action><Noun>RequestDTO` / `<Noun>ResponseDTO`. JSON tags are `snake_case`.
Common validators in use: `required`, `email`, `min=8`, `oneof=accepted rejected`.

### `store.go` — data access + the interface controllers depend on

```go
type Store struct {
	queries *sqlc.Queries
}

type OrganizationStore interface {   // named <Domain>Store; consumed by handlers
	CreateOrganization(ctx context.Context, params sqlc.CreateOrganizationParams) (*types.Organization, error)
	GetOrganizationById(ctx context.Context, id string) (*types.Organization, error)
}

func NewStore(db *pgx.Conn) *Store {
	return &Store{queries: sqlc.New(db)}
}
```

Conventions:
- Method params for inserts/updates are the **generated** `sqlc.<Query>Params` structs — the store does not define its own param types.
- **`pgx.ErrNoRows` is swallowed and returned as `(nil, nil)`** for "get" methods. Callers must nil-check, not `errors.Is` check. This is the single most important convention to preserve; controllers are written assuming it.
- List methods pre-size the slice: `make([]types.X, len(rows))` and index-assign.
- When several methods map the same row type, extract a `toX(row)` helper (see `organization/store.go: toOrganizationInvite`).

### `routes.go` — Handler struct, constructor, route table

```go
type Handler struct {
	store           OrganizationStore
	membershipStore membership.MemebershipStore   // cross-domain deps injected as interfaces
	userStore       user.UserStore
}

func NewHandler(store OrganizationStore, membershipStore membership.MemebershipStore, userStore user.UserStore) *Handler {
	return &Handler{store: store, membershipStore: membershipStore, userStore: userStore}
}

func (h *Handler) RegisterRoutes(router *mux.Router) {
	r := router.PathPrefix("/organization").Subrouter()
	r.Use(middleware.Auth)                     // auth applied per-subrouter, never globally
	r.HandleFunc("/create", h.HandleCreateOrganization).Methods(http.MethodPost)
	r.HandleFunc("/get/{id}", h.HandleGetOrganizationDetailsById).Methods(http.MethodGet)
}
```

A domain that needs another domain's data takes that domain's **interface** (e.g.
`user.UserStore`), never its concrete `*Store` and never its handler.

URL style in this codebase is verb-in-path, not pure REST:
`/create`, `/get/{id}`, `/list`, `/update`, `/delete/{id}`, `/change-owner/{id}`.

### `controllers.go` — handlers, one canonical shape

```go
func (c *Handler) HandleCreateOrganization(w http.ResponseWriter, r *http.Request) {
	// 1. decode
	var payload CreateOrganizationRequestDTO
	if err := utils.ParseJSON(r, &payload); err != nil {
		utils.WriteError(w, http.StatusBadRequest, err)
		return
	}
	// 2. validate
	if err := utils.Validate.Struct(payload); err != nil {
		utils.WriteError(w, http.StatusBadRequest, err)
		return
	}
	// 3. identity
	userId, ok := middleware.GetUserID(r.Context())
	if !ok {
		utils.WriteError(w, http.StatusUnauthorized, errors.New("Not authenticated"))
		return
	}
	// 4. authorization / business checks (ownership, role, duplicates) — each with early return
	// 5. store call(s)
	// 6. utils.WriteJSON(w, http.StatusCreated, result)
}
```

Note the receiver is `c *Handler` in `controllers.go` but `h *Handler` in `routes.go` — that
inconsistency exists in both current domains; match it or normalize it deliberately.

Status codes used: `200 OK`, `201 Created` (signup + creates), `400`, `401`, `404`, `500`.
Errors always serialize as `{"error": "<message>"}`.

## 5. Database workflow

The migration SQL is the source of truth. `sqlc.yaml` points at the migrations folder as its
schema, so **there is no separate schema file to keep in sync** — `db/schema.sql` is a
generated `pg_dump` snapshot for reading only.

```text
cmd/migrate/migrations/*.up.sql  ──► sqlc schema
db/queries/*.sql                 ──► sqlc queries
                    │
              make sqlc
                    ▼
              db/sqlc/*.go  (generated Go: models, params, methods)
```

`sqlc.yaml` config that matters:

```yaml
engine: postgresql
queries: db/queries
schema: cmd/migrate/migrations
gen:
  go:
    package: sqlc
    out: db/sqlc
    sql_package: pgx/v5
    emit_json_tags: true
    emit_empty_slices: true
    overrides:
      - db_type: uuid                     → go_type: string
      - db_type: timestamptz              → go_type: time.Time
      - db_type: pg_catalog.timestamptz   → go_type: time.Time
```

Consequence to know when writing migrations: `TIMESTAMPTZ` columns generate plain
`time.Time`, but bare `TIMESTAMP` columns generate `pgtype.Timestamp` and stores must read
`.Time` off them. The `users` table uses `TIMESTAMPTZ`; `organizations`, `memberships`, and
`organization_invites` use `TIMESTAMP` — which is why those stores write
`org.CreatedAt.Time` while the user store writes `user.CreatedAt`. Prefer `TIMESTAMPTZ` in
new tables for consistency.

Query file conventions (`db/queries/<table>.sql`):

```sql
-- name: CreateOrganization :one
INSERT INTO organizations (name, owner_id)
VALUES ($1, $2)
RETURNING id, name, owner_id, created_at;
```

- Annotations: `:one`, `:many`, `:exec`.
- Columns are listed explicitly — no `SELECT *`.
- Mutations that the app needs back use `RETURNING <explicit columns>`.
- Query names are PascalCase and become `Queries.<Name>` verbatim.

Postgres schema conventions: `UUID PRIMARY KEY DEFAULT gen_random_uuid()` (needs the
`pgcrypto` extension, enabled in the first migration), real `CREATE TYPE ... AS ENUM` for
roles/statuses, explicit `REFERENCES` foreign keys, composite PK on join tables
(`memberships (organization_id, user_id)`), and partial unique indexes for "one open X"
rules:

```sql
CREATE UNIQUE INDEX organization_invites_pending_unique
    ON organization_invites (organization_id, user_id)
    WHERE status = 'pending';
```

Enums generate typed Go constants — use them, never string literals:
`sqlc.MembershipsRoleSuperAdmin`, `sqlc.OrganizationInviteStatusPending`.

### Commands (all run from `server/`)

```bash
make migration add_projects_table   # scaffold up/down pair (needs the migrate CLI installed)
make migrate-up                     # apply ONE migration, then dump schema
make migrate-down                   # roll back ONE migration, then dump schema
make migrate-force 20260731003123   # fix bookkeeping only — runs no SQL
make schema-dump                    # refresh db/schema.sql
make sqlc                           # regenerate db/sqlc/
make build                          # go build -o build/taskboard-go-api cmd/main.go
make run                            # build + run
make clean
```

`up`/`down` move exactly **one** step (`m.Steps(±1)`), not "all pending". Down migrations
must drop in FK-dependency order (children first, then tables, then types). Full details in
[server/docs/1_MIGRATIONS.md](server/docs/1_MIGRATIONS.md).

## 6. Auth model

- Passwords: bcrypt at `DefaultCost`; `types.User.Password` is tagged `json:"-"` so it never serializes.
- JWT: HS256, custom claims struct embedding `jwt.RegisteredClaims` with a `UserId` field serialized as `id`; issuer `taskboard-go-api`; expiry `JWT_EXPIRATION` **minutes** (default 15).

  ```go
  type Claims struct {
  	UserId string `json:"id"`
  	jwt.RegisteredClaims
  }
  ```

- Transport: `auth.GetToken(r)` tries the `token` cookie first, then falls back to `Authorization: Bearer <token>`.
- Cookie is `HttpOnly`, `SameSite=Lax`, `Path=/`, `Secure:false` (marked "set true in production").
- `middleware.Auth` verifies the token and stashes the user id under a private
  `contextKey("userID")`; handlers read it with `middleware.GetUserID(ctx)` and must handle `ok == false`.
- Authorization (role checks) is **not** middleware — it lives inline in controllers, querying
  `membershipStore.GetMembershipByUserAndOrganization` or `store.CheckIfUserIsOwner`.

Roles enum: `super_admin | admin | manager | member`. Org creator gets `super_admin`;
accepted invitees get `member`. Ownership is tracked separately on `organizations.owner_id`.

## 7. Repo rules (enforced conventions)

From `server/.cursor/rules/`:

1. **Never run migration commands.** Agents may write/edit files under `cmd/migrate/migrations/`, but `make migrate-*`, `go run cmd/migrate/main.go`, and the `migrate` CLI are the user's to run. Tell the user which command to run.
2. **Every route ships with docs.** Any change to a `RegisterRoutes` requires adding/updating a markdown file in `server/docs/api/` (grouped by domain) with method, path, auth requirement, and a working `curl` including a dummy JSON body.

Also implied by the codebase and the Makefile comment in `challange.md`: every project command
belongs in the `Makefile`, not in ad-hoc shell instructions.

Never hand-edit: `db/sqlc/**` (regenerate with `make sqlc`) and `db/schema.sql`
(regenerate with `make schema-dump`).

## 8. Adding a new domain — checklist

Using `projects` as the example:

1. `make migration create_projects_table` → fill in `.up.sql` and the exact reverse `.down.sql`.
2. Tell the user to run `make migrate-up`.
3. Write `db/queries/projects.sql` with `-- name: X :one|:many|:exec` annotations.
4. `make sqlc` → new `db/sqlc/projects.sql.go` + models.
5. Add the domain model to `types/types.go` (JSON tags, `validate` tags where useful).
   Several future models — `Project`, `Task`, `Comments`, `Label`, `TaskLabel` — are already stubbed there.
6. Create `service/project/` with `store.go` (`Store` + `ProjectStore` interface + `NewStore(*pgx.Conn)`), `dto.go`, `routes.go` (`Handler` + `NewHandler` + `RegisterRoutes`), `controllers.go`.
7. Wire it in [server/cmd/api/api.go](server/cmd/api/api.go):
   ```go
   projectStore := project.NewStore(s.db)
   projectHandler := project.NewHandler(projectStore, organizationStore, membershipStore)
   projectHandler.RegisterRoutes(subRouter)
   ```
8. Add `server/docs/api/project.md` with curl examples (rule #2 above).

## 9. Runtime & config

`cmd/main.go` boot sequence: `config.Envs` (package-level global, `.env` loaded at init) →
`db.NewPostgresStorage` → `conn.Ping` → `api.NewApiServer(":"+PORT, conn).Run()`.
Any DB failure is `log.Fatal`.

| Env var | Default | Used by |
| --- | --- | --- |
| `DATABASE_URL` | `postgresql://test` | app + migrate CLI + `make schema-dump` |
| `PORT` | `8080` | HTTP listener, Dockerfile `EXPOSE` |
| `JWT_KEY` | `secret` | HS256 signing |
| `JWT_EXPIRATION` | `15` (minutes) | token expiry + cookie `MaxAge` (×60) |

`godotenv.Load()` failing is logged, not fatal — containers inject env vars directly.

Docker: builds `CGO_ENABLED=0` static binary in `golang:1.25-alpine`, copies it into
`alpine:3.24` with `ca-certificates` + `tzdata`, runs as uid `10001` (`appuser`).

## 10. Known gaps in the current implementation

Relevant if you generate a starter template from this — these are deliberate notes, not a
description of what the code already does:

- **Single connection, not a pool.** `db.NewPostgresStorage` returns `*pgx.Conn` and every store takes `*pgx.Conn`. `pgxpool.Pool` would be the production choice; switching means changing `NewStore` signatures (`sqlc.New` accepts any `DBTX`, so the generated layer needs no change).
- **No transactions yet.** `sqlc` generated `Queries.WithTx(pgx.Tx)`, but nothing calls it. Multi-step flows (create org + owner membership; accept invite + create membership) currently run as separate statements and can half-apply.
- **No graceful shutdown, no timeouts.** `http.ListenAndServe` with no `http.Server` struct, so no read/write/idle timeouts and no signal handling.
- **No CORS middleware** — needed once `client/` is populated.
- **No tests.** No `_test.go` anywhere; the store interfaces exist and make handlers mockable, so table-driven handler tests are the natural first addition.
- **`GetUsersList` selects the password column** and `types.User` hides it only via `json:"-"`; there's no separate public user projection.
- **Signup relies on the `(nil, nil)`-on-no-rows convention**; changing that convention breaks `HandleSignup`'s duplicate check.
- **No pagination / filtering / sorting / search / soft delete** yet — all specified in [server/challange.md](server/challange.md) as remaining work, along with the `projects`, `tasks`, `comments`, `labels`, `task_labels` domains.
